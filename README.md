# Stackora — production build

Two-page architecture: `index.html` (homepage) and `article.html` (one
template for every review). The frontend is frozen — adding, editing,
promoting, or removing content only ever touches files under `data/`.
HTML/CSS/JS never need to change for routine content operations.

## File map

```
/
├── index.html              Homepage (Featured / Latest Reviews / category feed)
├── article.html            Single template for every review
├── 404.html
├── _routes.json            Cloudflare Pages: only /article.html needs edge processing
├── robots.txt
├── sitemap.xml
├── css/
│   └── style.css           One shared stylesheet
├── js/
│   ├── utils.js            Shared: router, SEO meta helpers, shared nav wiring
│   ├── search.js           Shared: search overlay + index (used by both pages)
│   ├── main.js              index.html only: home/category/pagination rendering
│   └── article.js           article.html only: article rendering
├── functions/
│   └── [[path]].js         Edge SEO rewrite for /article.html?slug=... (title,
│                            description, canonical, OG/Twitter tags, JSON-LD)
├── assets/
│   ├── favicon.svg
│   └── og-default.jpg
└── data/
    ├── homepage.json       Hero copy, site totals, and featured picks
    ├── affiliate-links.json   { affiliateKey: url }
    ├── categories.json     Registry of nav categories + their page counts
    ├── search-index.json   Search box + related-post lookups
    ├── pages/
    │   ├── page-1.json     Full paginated feed (Latest Reviews), 12/page
    │   └── page-2.json
    ├── categories/
    │   └── <slug>/
    │       └── page-1.json   { posts, total, totalPages } for that category
    └── articles/
        ├── meta/<slug>.json    Title, excerpt, image, dates, pros/cons, FAQ, related
        └── html/<slug>.html    The article body only
```

## Backend workflows (frontend never changes for any of these)

**Add a new post**
1. Create `data/articles/meta/<slug>.json` and `data/articles/html/<slug>.html`.
2. Add it to the right `data/pages/page-N.json` (append a new page once the
   current last page hits 12 posts) and to its `data/categories/<cat>/page-N.json`.
3. Add it to `data/search-index.json`.
4. Add a `<url>` entry to `sitemap.xml` (absolute URL, see note below).
5. Bump `data/homepage.json`'s `totalPosts`/`totalPages`.

**Promote a post to Featured**
Edit `data/homepage.json`'s `featured` array — it holds full post objects
(not just slugs), so the homepage renders it with zero extra lookups.

**Change an affiliate link**
Edit `data/affiliate-links.json`. Every article referencing that
`affiliateKey` updates immediately — nothing else to touch.

**Edit or delete a post**
Edit: overwrite its `meta/<slug>.json` and/or `html/<slug>.html` in place.
Delete: remove those two files, then remove its entries from
`pages/page-N.json`, its `categories/<cat>/page-N.json`, `search-index.json`,
`sitemap.xml`, and `homepage.json.featured` if it was featured.

## The one place a domain is hardcoded

Everything in `js/*.js` and `functions/[[path]].js` derives the domain from
the request itself, so there's nothing to edit there. `sitemap.xml` is the
exception — sitemaps require absolute URLs by spec (a `sitemap.json` isn't a
format search engines recognize, so it stays XML). Replace
`https://YOUR-DOMAIN.com` with your real domain, ideally regenerated by
automation whenever articles are added or removed.

## Performance / stability choices made deliberately

- **No `_headers`, no service worker.** Cloudflare's CDN and the browser's
  own cache already handle this for static files; adding a manual layer on
  top is exactly the kind of thing that needs upkeep later.
- **`_routes.json`** limits the edge Function to `/article.html` only —
  every other request (CSS, JS, images, all of `data/`) is served straight
  from the CDN with zero Worker invocation, which matters once you're at
  hundreds of pages getting crawled and clicked through constantly.
- **Same-page changes (pagination, category, search result → another
  article) use `pushState` and re-render in place — no full reload.**
  Going from the homepage to an article (or back) is a real navigation
  between two different static files, which is unavoidable once they're
  separate documents, but both are tiny, CDN-cached, and only
  `article.html` ever touches the edge Function.
- Non-critical fetches (the affiliate link, related posts) fail
  independently — a slow or missing `affiliate-links.json` never blanks
  out an otherwise-working article.
- Every category in the nav has a `data/categories/<slug>/page-1.json`,
  including ones with zero posts so far (`domain`, `cybersecurity`) — they
  show a normal "No posts found" instead of an error.

## Deploy

1. Push this folder to a GitHub repo (root of repo = root of site).
2. Cloudflare Pages → connect the repo. Build command: empty. Output
   directory: `/`.
3. Deploy — `functions/[[path]].js` and `_routes.json` are auto-detected,
   no extra config.
4. Test in an incognito window so you're not looking at a stale cache.
